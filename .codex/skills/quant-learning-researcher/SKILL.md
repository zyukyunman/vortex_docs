# 量化学习研究

把这个仓库当作学习系统，而不是生产代码仓库。

## 边界

- 不在这里实现策略、因子、回测、执行或实盘交易代码。
- 除非用户明确要求桥接或 handoff，不主动检查 `vortex_quant`。
- 已经绑定 Vortex 本地数据、runner、artifact、preset、交易链路或因子实验的研究结论，应沉淀在 `vortex_quant/docs`，不放在这里。
- 可以写公式、伪代码、图和实现要求，用来说明可行性。
- 对近期论文、市场实践、产品文档或可能变化的事实，需要获取当前来源。
- 写持久笔记时遵循本地 `obsidian` skill 的 frontmatter、wikilink、MOC 和断链校验规则。

## 流程

1. 识别资料类型：论文、书籍章节、文章、研报、文档、访谈或用户想法。
2. 记录来源信息：标题、作者、年份、路径或链接、主题标签、来源质量。
3. 抽取核心问题：它试图解决什么问题。
4. 解释机制：经济直觉、因果链、模型结构或系统原则。
5. 区分证据和观点：数据、市场、样本区间、指标和限制。
6. 谨慎迁移：它对 A 股、量化系统、AI 模型训练或研究流程有什么可迁移点。
7. 决定沉淀形态：阅读笔记、主题综述、可行性 memo、skill 候选或实现前检查清单。

## 阅读笔记结构

使用 Obsidian frontmatter，并保留这些中文章节：

- `来源`
- `问题`
- `机制`
- `证据`
- `边界`
- `可迁移点`
- `下一步`

## 可行性视角

当资料暗示一个量化想法时，检查：

- 所需数据是否真实可得，是否点时安全。
- 最小可证伪实验是什么。
- 可能的未来函数、过拟合、容量和交易成本风险。
- 它是研究假设、系统方法、AI 建模方法，还是职业/行业认知。

## 实现交接规则

默认不创建给 `vortex_quant` 的独立 handoff 文档；让实现仓库直接读取本仓库的来源笔记或 skill。只有用户明确要求时，才写实现前检查清单。检查清单只描述来源、假设、所需数据、最小可证伪实验和风险，不写代码，不复制知识正文。
