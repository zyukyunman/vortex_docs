# 量化技能提炼

只有当一个方法会改变未来智能体行为时，才创建技能。

## 创建前检查

确认材料是否满足：

- 未来会反复使用。
- 足够流程化，能指导 智能体 行动。
- 可以简短表达，不需要复制大量来源内容。
- 与已有 skill 不重复。

如果只是一次性洞见，写知识笔记，不创建 skill。

## 技能要求

每个 skill 只需要：

- 一个 `SKILL.md`，包含 YAML frontmatter。
- 必要时增加 `references/`，用于承载详细背景，避免 `SKILL.md` 过长。

不要在技能文件夹里加说明书、变更日志、安装说明或过程叙事。
来源分析和书目信息放在 `knowledge/` 的 Obsidian 笔记里，再从相关 MOC 链接。

## 技能文件结构

使用：

```markdown
---
name: short-skill-name
description: 用于……
---

# 技能标题

## 边界

## 流程

## 输出
```

正文要短。详细来源笔记放在 `knowledge/`，不要塞进 skill。

## 来源处理

- 不粘贴受版权保护书籍或文章的大段原文。
- 相关知识笔记中保留来源路径和书目信息。
- 如果技能基于单一来源，在正文中标注为“基于单一来源的初版”。
- 如果技能结合多来源和多轮用户决策，可以写成更稳定的流程规则。

## 仓库边界

本仓库的技能应支持学习、综合、可行性评审或交接准备，不应指示智能体在这里写生产策略、回测或交易代码。
