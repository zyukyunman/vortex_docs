# 知识沉淀流程

## 入口

新材料先进入以下位置：

- [[待处理材料入口]]：临时文章、网页摘录、对话输入、待处理材料。
- [[书籍库]]：书籍 PDF、电子书、长篇教材。
- [[论文库]]：论文、工作论文、技术报告。

## 处理步骤

1. 识别材料类型：论文、书、博客、研报、技术文档、访谈、课程或对话。
2. 建立 source card：标题、作者、年份、路径或链接、可信度、主题标签。
3. 做阅读笔记：问题、机制、证据、假设、限制、反例、适用市场。
4. 做可行性判断：数据是否可得、是否容易有未来函数、是否能被最小实验验证。
5. 判断沉淀形态：知识卡、主题综述、技能，或实现仓库交接备忘录。

## 输出模板

阅读笔记建议包含：

- `来源`：来源、作者、年份、路径或链接。
- `Question`：它试图解决什么问题。
- `Mechanism`：核心机制或因果链条。
- `Evidence`：用什么证据支持。
- `Limits`：样本、市场、假设和失败条件。
- `可迁移点`：对 A 股、量化系统、AI 模型训练或个人研究方法有什么迁移价值。
- `Next`：下一步应该读什么、问什么或验证什么。

## 进入技能的标准

不要因为单篇文章看起来有趣就立刻创建技能。适合创建技能的情况：

- 这个流程会反复使用。
- 它能稳定改善 智能体 的阅读、判断或输出质量。
- 它有清晰触发条件。
- 它能用简短步骤表达，不需要塞入大量原文内容。

## 进入 vortex_quant 的标准

只有当用户明确希望进入实现，或某个想法已经具备足够证据时，才写交接备忘录。交接备忘录只描述实现前提和风险，不在本仓库落代码。
