# 仓库定位与边界

## 一句话定位

`vortex_docs` 是量化研究学习与知识沉淀仓库。它负责扩大认知、整理证据、形成假设和沉淀方法；不负责实现策略、回测框架或交易系统。它的顶层入口是 [[知识库结构总览]]。

## 核心边界

可以做：

- 论文、书籍、研报、博客、开源文档的阅读与综合。
- 研究方向的早期假设生成。
- AI 模型训练、特征工程、评估方法、系统设计的概念拆解。
- 对一个想法是否值得进入实现仓库做可行性判断。
- 把高频重复流程沉淀成本地技能。
- 保存外部输入的来源、机制和开放问题，让 [[知识库总览]] 能作为上游研究线索库。

不要做：

- 写生产因子代码、策略代码、回测 runner、交易执行代码。
- 直接修改 `vortex_quant` 的策略或实盘路径。
- 把 `vortex_quant` 现有结论当作这里的默认思维框架。
- 沉淀已经和 Vortex 本地数据、runner、artifact、preset 或交易链路绑定的因子研究结论。
- 维护产品、架构、代码功能、用户手册或运行规则；这些属于 `vortex_quant`。

## 归属判定

判断一条材料放在哪里，用下面的规则：

| 内容 | 默认归属 | 说明 |
|---|---|---|
| 书籍、论文、研报、文章、访谈、网页材料 | `vortex_docs` | 作为外部输入和探索性知识保存 |
| 只讨论机制、假设来源、开放问题的投资思想 | `vortex_docs` | 不绑定 Vortex 代码和本地数据 |
| 使用 Vortex 数据字段、runner、回测结果或 artifact 的因子研究 | `vortex_quant/docs` | 属于实现仓库的研究资产 |
| 和策略 preset、交易、QMT、执行、风控、报告 schema 绑定的投资框架 | `vortex_quant/docs` | 属于产品/代码/运行文档 |
| 产品原型、架构设计、CLI/API、用户手册 | `vortex_quant/docs` | 不迁到本知识库 |

## 与 vortex_quant 的分工

`vortex_docs` 更像研究图书馆和方法实验室，`vortex_quant` 更像工程化实现和运行仓库。

这里可以产生“值得测试的想法”，但默认只保留来源、机制和可行性判断。进入 `vortex_quant` 后，因子实验、策略研究结论和代码绑定的投资框架应沉淀在 `vortex_quant/docs`，并链接回本仓库的来源材料。

若用户明确要求把一个上游想法交给实现仓库，才需要单独写清楚：

- 想法来源。
- 核心机制。
- 所需数据。
- 最小可证伪实验。
- 未来函数与过拟合风险。
- 为什么值得占用实现仓库空间。

## 对 智能体 的要求

在这个仓库里工作时，智能体应该保持开放性和独立判断。可以参考 `vortex_quant` 的组织结构，但不要默认读取或复述它的研究内容。

如果用户给新文章或新书，先理解来源和机制，再判断是否应该沉淀为知识卡、主题笔记或技能。不要主动把它包装成 `vortex_quant` 研究结论；一旦进入 Vortex 数据、回测、因子实验或策略晋升，后续记录应回到 `vortex_quant/docs`。
