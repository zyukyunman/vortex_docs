# AI量化系统开发项目故事库

## 一、商汤：真值采测一体方案

### 1. 一分钟版本

我在商汤做过一个真值采测一体方案，从 0 到 1 搭建真值采集车和真值数据云。这个项目的核心不是某个单点功能，而是把车端采集、云端产线、录制回放、数据格式、质量监控和诊断流程串成一条稳定链路。我负责软硬件方案落地、版本管理、部署流程、统一录制回放和诊断体系。这个项目最能代表我的地方，是我擅长把复杂数据链路做成**可录制、可回放、可验证、可定位问题**的系统。

### 2. 三分钟版本

这个项目最开始的难点，不是某个技术点做不出来，而是整条链路很散：车端采集、云端处理、不同传感器、不同项目环境、不同地区回灌，大家都在各自做，但系统层面缺少统一性。

我在里面做的事情主要有四块。第一是参与车端和云端整体方案落地，保证采集链路真正跑起来，不只是 demo。第二是把录制、解析、回放几个关键环节统一起来，推动数据格式标准化，减少链路之间的摩擦。第三是做实车回灌一致性，核心目标是让回放尽可能稳定复现实车的 sensor 表现，不因为地区、设备或运行次数不同而漂。第四是把质量监控和诊断流程建起来，让新项目上线、车端环境检查、项目启停这些事情不再完全依赖经验。

如果把这段经历翻译成量化系统语言，它对应的其实就是：**数据回放仿真、链路一致性验证、系统可信度建设、异常诊断和问题归因能力**。这也是我认为自己适合量化系统工程切入点的原因。

### 3. STAR 版本

**S（背景）**  
真值采集车和真值数据云需要从 0 到 1 搭起来，涉及车端采集、云端产线、数据录制回放、诊断监控等多个环节，链路长、参与方多、环境复杂。

**T（任务）**  
把真值采测链路搭成一个稳定可用、可复现、可持续迭代的系统，而不是零散功能拼接。

**A（行动）**  
1. 参与车端软硬件方案落地和云端产线功能开发。  
2. 负责版本管理、研发部署流程，保证车端和云端协作有序推进。  
3. 实现统一录制 / 回放方案，推动数据格式标准化。  
4. 做实车回灌一致性，提升跨地区、多次回放的稳定性。  
5. 建立质量监控和诊断流程，支持新项目快速拉通。

**R（结果）**  
这套方案把采集、回放、解析、诊断这些关键能力真正连起来了，提升了数据链路的一致性和可复现性，也让新项目上线和问题定位效率更高。

### 4. 对应量化岗位的翻译版本

如果放到量化系统里，这段经历最像的是：

1. 市场数据或研究数据链路建设；
2. 回放仿真 / shadow trading；
3. 链路一致性验证；
4. 执行前验证与系统可信度建设；
5. 出问题后的归因与诊断框架。

## 二、商汤：基础组件 / Sensor 技术负责人

### 1. 一分钟版本

我在商汤后面还承担了基础组件和 sensor 方向的技术负责人角色，做的事情包括 daemon、软件部署、CI、3rdparty、时间同步，以及 Camera、Lidar、INS、Radar 的接入、采集、回放、解析。我比较核心的价值，不是把某个设备点亮，而是让这些能力可以跨项目复用、快速适配、稳定运行，支撑算法和数据侧快速迭代。

### 2. 三分钟版本

这个阶段我开始更多站在平台和系统层面看问题。因为量产项目很多、硬件平台很多、业务需求也很多，如果每个项目都重新做一遍接入、部署、同步和回放，团队效率会非常低，而且链路质量很难稳定。

所以我做的重点，是把一些共性的基础能力做成组件和流程。包括 daemon、部署、CI、3rdparty、时间同步这些基础组件，也包括 Camera、Lidar、INS、Radar 等传感器的接入、采集、回放和解析。除了功能本身，我还参与量产方案设计与评审，对接算法、数据、路测、真值等多个团队的需求，并推动新车上线、集成测试和发版流程。

如果放到量化系统视角，这段经历最像的是**数据基础设施、回放框架、研究平台底座、执行前验证能力和系统平台化建设**。它说明我不是只会写单点功能，而是能把复杂链路做成可复用、可维护、能持续迭代的平台能力。

### 3. STAR 版本

**S（背景）**  
多项目、多硬件平台并行推进，传感器接入、时间同步、回放和部署能力重复建设严重，影响研发效率和系统稳定性。

**T（任务）**  
把共性的底层能力抽出来，做成跨项目可复用的基础组件和流程。

**A（行动）**  
1. 负责 daemon、部署、CI、3rdparty、时间同步等基础组件设计与开发。  
2. 负责多类传感器接入、采集、回放、解析功能建设。  
3. 参与方案设计与评审，衔接算法、数据、测试和硬件团队。  
4. 规划开发与发版流程，提升项目 bringup 和后续迭代效率。

**R（结果）**  
基础能力更标准化、复用性更高，项目接入和迭代效率提升，算法与数据侧也能更快建立在稳定底座上推进工作。

### 4. 对应量化岗位的翻译版本

这段经历对应量化里的：

1. 数据基础设施；
2. 行情/研究数据接入底座；
3. 回放框架与模拟验证；
4. 平台工程与流程工程化；
5. 研究到生产之间的基础能力建设。

## 三、顺丰：慧眼神瞳 AIOT 平台

### 1. 一分钟版本

在顺丰，我参与并推动了新部门第一个 AI 系统从 0 到 1 落地。项目核心是做一个云边端协同的一体化 AI 平台，支持视频流接入、算法集成、边缘部署、设备管理和服务化上线。我在里面做过算法集成、平台迁移、边云协同和设备管理服务，这段经历最能说明我具备**builder 能力**，能把一个能跑的技术方案做成可推广、可运维的系统。

### 2. 三分钟版本

顺丰这个项目对我影响很大，因为它让我第一次完整经历一个 AI 系统从 0 到 1 的过程。最开始团队是新的，业务要求是要把 AI 能力真正落到全国网点和中转场，而不是停留在单点实验。

我负责的事情包括视频流接入、算法集成、边缘设备上的部署优化，也包括边缘设备和云平台之间的交互、设备管理、故障和心跳上报，以及把部分算法业务服务化上线到云平台。这里面有两个很重要的点：第一，系统不是单机程序，而是有边、有云、有设备管理、有运维监控的完整链路；第二，很多事情不是局部最优，而是为了整体落地、整体稳定和整体成本做取舍。

如果把这段经历翻译到量化或 AI 投资创业公司的语境里，它对应的是：**从零到一的平台建设、AI 系统工程、模型服务化、工程化治理、边界模糊场景下的 owner 意识**。这也是为什么我判断自己对 AI 投资创业公司会更有天然匹配。

### 3. STAR 版本

**S（背景）**  
新部门希望建设云边端协同的 AI 平台，把算法能力落到真实物流场景，覆盖设备接入、算法部署、监控和业务推广。

**T（任务）**  
把首个 AI 系统从概念和单点功能，做成可部署、可管理、可推广的实际系统。

**A（行动）**  
1. 基于 DeepStream 和 TensorRT 完成算法集成与边缘部署。  
2. 负责 x86 显卡方案向 Jetson Xavier 的迁移。  
3. 实现边缘设备与云平台交互、设备管理、故障与心跳上报。  
4. 推动算法服务化上线，让部分业务迁移至算法云平台。

**R（结果）**  
系统完成从 0 到 1 落地，具备边云协同、设备管理和云端扩展能力，支撑业务进一步推广和稳定运行。

### 4. 对应 AI 投资创业公司的翻译版本

如果面 AI 投资创业公司，这段经历要强调的是：

1. 我做过从 0 到 1；
2. 我知道怎么把模型或算法能力做成系统；
3. 我习惯处理跨模块问题，而不是只做单点开发；
4. 我对系统部署、监控、服务化和长期运行负责过。

## 五、你面试时最该记住的用法

1. 面头部量化：先讲商汤，再少量补顺丰。
2. 面 AI 投资创业公司：先讲顺丰，再用商汤补强系统可信度和数据链路能力。
