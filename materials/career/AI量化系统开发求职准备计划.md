# AI量化系统开发职业定位总览

## 一句话结论

这份材料只服务一个问题：如何把自动驾驶、AIoT、传感器和复杂系统工程经验，翻译成量化系统开发能听懂、能相信、能判断价值的职业叙事。

它不是量化研究路线，也不是策略学习路线。真正的研究学习入口应回到 [[量化因子研究入口地图]]、[[量化研究书单与阅读路线]] 和 [[研究方法知识]]。

## 对外定位

推荐定位：

> 我是做 AI 系统工程和复杂实时系统落地出身的工程师，长期处理多源数据接入、时间同步、采集回放、诊断复现、基础组件平台化和 AI 系统上线。现在希望把这套能力迁移到量化系统开发，主攻数据链路、回放仿真、执行风控、研究平台和 AI 策略工程化。

这个定位有三个好处：

- 不假装自己是量化研究员。
- 不把优势压缩成“会 C++”。
- 直接把过往经历落到量化系统的真实工程问题上。

## 主线岗位

优先主打：

| 方向 | 匹配度 | 原因 |
| --- | --- | --- |
| 数据基础设施 / 行情数据 / 回放仿真 | 高 | 多源数据接入、时间同步、采集回放、质量监控经验高度迁移 |
| 模拟盘 / shadow trading / 交易仿真 | 高 | 离线回放、线上一致性、问题复现和偏差诊断经验可迁移 |
| 执行系统 / OMS / EMS / 风控 | 中高 | 实时状态机、异常处理、fail-closed、链路诊断能力匹配，但需要补交易业务语境 |
| 研究平台工程 | 中高 | 平台化、实验流程、数据语义和复现能力匹配，但需要补因子研究 workflow |
| AI 策略工程 / MLOps | 中高 | AI 系统落地、模型服务、版本治理和部署经验可迁移，尤其适合 AI 投资创业公司 |

暂时不主打：

- 纯量化研究员：金融市场、因子研究、组合理论和实证积累不足。
- 高频低延迟核心交易内核：有 C++ 和实时系统基础，但缺少交易所协议、微观结构和极致低延迟交易链路经验。
- 泛后端工具岗：如果不能进入数据、研究、执行或 AI 平台主链路，长期价值有限。

## 能力迁移表

| 过往能力 | 量化系统里的对应价值 |
| --- | --- |
| Camera / Lidar / INS / Radar 多源接入 | 行情、财务、公告、替代数据接入与统一建模 |
| GPTP/PTP、设备授时、时间同步 | 行情时间戳、订单事件顺序、Point-in-Time 语义 |
| 采集、录制、回放、解析 | market replay、订单回放、模拟盘、shadow trading |
| 实车回灌一致性、质量监控 | 回测/模拟/实盘偏差诊断与系统可信度 |
| 基础组件、部署、CI、3rdparty | 研究平台、执行平台、服务治理和工程底座 |
| 顺丰 AIoT 从 0 到 1 | AI 投资创业公司的 builder 能力 |
| 跨算法、硬件、测试、云端、车端协作 | 研究、工程、交易、风控、运维之间的接口协调 |

## 真实短板

需要正面承认：

- 没有专业量化团队生产经验。
- 对交易系统业务语境还要补：OMS、EMS、PMS、订单状态、券商接口、对账、成交归因。
- 对量化研究 workflow 还要补：因子、特征、回测、实验管理、数据版本和点时安全。
- Python 量化平台表达需要加强，不能只停留在辅助脚本层面。

成熟表达：

> 我的短板不是工程本身，而是量化行业语境和真实交易链路经验。我会优先补交易执行、回测可信度、模拟盘、风控、数据版本和模型部署，而不是泛泛学金融概念。

## 准备优先级

1. 职业叙事：把“自动驾驶/AIoT”翻译成“强时序数据系统、回放仿真、执行可靠性、AI 系统工程”。
2. 交易系统语境：target position、order、OMS/EMS/PMS、pre-trade risk、post-trade risk、broker gateway、reconciliation。
3. 市场规则对工程的影响：T+1、涨跌停、停牌、ST、集合竞价、流动性、容量、滑点。
4. 回测可信度：Point-in-Time、未来函数、幸存者偏差、复权、成本、成交假设、样本外。
5. Python 量化平台：pandas、numpy、DuckDB、parquet、配置、日志、CLI、实验归档。
6. AI 投资工程：特征版本、模型版本、策略版本、模型部署、监控、回滚、研究到执行链路。

## 公司路径

### 头部成熟量化

打法：

- 不泛投“量化开发”。
- 只投与数据、仿真、执行、风控、研究平台、AI 平台明确相关的岗位。
- 面试表达要更垂直，强调某一段链路的可迁移能力。

风险：

- 业务语境要求高。
- 岗位更垂直，竞争者可能已有量化系统经验。
- 不适合用“我学习快”这种弱表达。

### AI 投资创业公司

打法：

- 强调 builder、AI 系统工程、跨模块拉通、从 0 到 1。
- 说明自己能把研究、数据、模型、模拟、执行和监控逐步串成系统。
- 重点证明不是只会单点开发，而是能拥有一条链路。

风险：

- 如果公司其实只要能赚钱的研究员，则不匹配。
- 如果 AI 只是招聘话术，实际缺乏系统建设意识，也要谨慎。
- 边界可能模糊，必须问清 owner 范围。

## 面试叙事骨架

### 一分钟自我介绍

我过去主要做自动驾驶和 AIoT 复杂系统研发，核心经验不是单点算法，而是多源实时数据接入、时间同步、采集回放、诊断复现、基础组件平台化和 AI 系统落地。在商汤，我长期负责传感器接入、数采回放、时间同步、基础组件和真值采测一体方案；在顺丰，我做过新部门首个 AI 系统从零到一落地，覆盖边云协同、设备管理和服务化上线。

我现在想切到量化系统开发，是因为量化系统同样需要强时序数据链路、回放验证、执行可靠性、风控和工程闭环。我不会把自己包装成研究员，更适合从数据基础设施、回放仿真、执行风控、研究平台和 AI 策略工程化切入。

### 为什么不是纯研究

我的核心优势不是策略想法本身，而是把复杂链路做稳定、做可验证、做能长期迭代。纯研究岗更看重建模、统计、因子理解和策略想法；我更擅长把研究、数据、回测、模拟、执行之间的系统链路做扎实。

### 为什么不是直接主打低延迟

低延迟核心岗通常要求非常具体的交易链路经验、交易所协议、网络栈和极限性能调优经验。我有 C++、性能优化和实时系统意识，但当前更准确的切入点是数据链路、回放仿真、执行风控、研究平台和 AI 策略工程。
